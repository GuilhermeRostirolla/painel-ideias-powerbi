# Ideas Program Dashboard · Python + SQL Server + Power BI

[Versão em português](README.md)

> **Every company has people with good ideas. Few know what happens to those ideas after they are submitted.**

![Dashboard tour](docs/img/painel.gif)

This dashboard tracks the performance of an **employee ideas program** inside a company, a program aimed not only at **continuous improvement** but also at **innovation**. Any employee, from the shop floor to the office, submits an idea through a form on an idea-management platform: cutting waste, saving time in a process, making a task safer or improving the customer experience.

From there, each idea goes through a journey:

**Evaluation → Solution Proposal → Approved → Being Implemented → Validation → Implemented**

Along the way, some ideas are rejected, some are cancelled and some go back to the idea bank to mature. The problem is that this journey is usually invisible: nobody knows how many ideas are stuck, where they stall, how much money they generate or who is actually taking part.

**The dashboard makes the journey visible.** In a few clicks, leadership sees the whole funnel, the lead-time bottlenecks, the financial return and people's engagement. The program stops being a suggestion box and starts being managed with KPIs, targets and SLAs.

> The dashboard itself is in Portuguese (Brazil).

### Questions the dashboard answers

- **Volume and conversion:** how many ideas come in each month, how many get implemented and what the approval rate is.
- **Lead time (SLA):** how long each idea stays in each stage, which ones are over the SLA and which have been stuck for more than 60 days.
- **Flow:** which status changes happened in the month and which ideas moved forward, stalled or went back.
- **Financial return:** planned investment, actual investment and estimated 12-month gain, by company and by status.
- **Engagement:** how many employees take part, who contributes most and how each company compares to the target.
- **Detail:** the full list of ideas in each stage, with author, company, theme and days in stage.

### The simulated scenario

- **872 ideas** from **6 companies** and about **2,200 employees**, from Jan/2024 to Sep/2026.
- Targets: **60-day overall SLA**, per-stage SLA (Evaluation 15 d, Proposal 45 d, Approved 30 d, Implementation 90 d, Validation 20 d), **50% engagement** and **15% conversion** to implementation.
- Period, company and campaign filters on every page.

### Why the data is synthetic

This dashboard is inspired by a real ideas-program project. Employee ideas, names, investment amounts and gains are **sensitive information**, so I rebuilt everything from scratch with a **Python simulator**: people, companies, titles, dates and values are generated by the simulator and loaded into SQL Server.

The simulator does not just draw random numbers. It reproduces how a real program behaves: each idea moves through the stages as a state machine, with variable time in each stage, rework, rejections and cancellations, and each company has its own financial-return profile. The result is a dashboard that looks like real data with **no real data** in it.

## Architecture

```
Python (simulator)  ──▶  SQL Server · dw schema (star schema)  ──▶  bi schema (views)  ──▶  Power BI
```

| Layer | What it does |
|---|---|
| **Python** (`gerador/`) | Simulates each idea's life cycle as a state machine, generates people, companies and values, and validates everything before loading. |
| **SQL Server** (`sql/`) | Star schema in the `dw` schema: fact and dimension tables with named PK, FK, UNIQUE and CHECK constraints and an index on every foreign key. The `bi` schema holds the views Power BI reads. |
| **Power BI** (`powerbi/`) | PBIP project (TMDL + PBIR) with 6 pages: Overview, SLA & Flow, Implemented, Financial, People and Idea Detail. |

## Design decisions

| Decision | Why |
|---|---|
| **Star schema in `dw`, views in `bi`** | Separates how data is stored from how it is consumed. The database follows naming and integrity standards (PK, FK, CHECK); the views give Power BI exactly the columns it uses. The database can change without breaking the report. |
| **Simulator as a state machine, not random rows** | SLA, aging and funnel KPIs only make sense if dates and stages are consistent with each other. Each idea "lives" its journey, with lognormal durations, rework and rejections. |
| **Reference date stored in the database instead of `TODAY()`** | Numbers do not drift with the calendar or break at month boundaries. Together with `--semente` (seed), anyone can reproduce exactly the same dashboard. |
| **Validate before loading, check after** | If anything is inconsistent (future date, broken stage chain, duplicate name), the load stops. Better to fail early than to show leadership a wrong number. |
| **Explicit targets and SLAs** | Without targets a dashboard only describes. With per-stage SLAs and engagement and conversion targets, it shows where to act. |
| **PBIP (TMDL + PBIR) instead of `.pbix`** | The model and report become text: versioned in Git, reviewable line by line and scriptable. |
| **Lean model** | Unused tables, columns and measures were removed. The model has 240 measures, all validated against the database. |

## How to run

Requirements: Python 3.12+, SQL Server (local, Windows authentication), ODBC Driver 18 and Power BI Desktop.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
python -m gerador.main --sem-blocklist --semente 501844422 --data-referencia 2026-09-30
```

This creates the `IdeiasDemo` database, runs `sql/01_schema.sql`, loads the data, creates the views in `sql/03_views_compat.sql` and runs the checks. Then open `powerbi/PainelIdeias.pbip` in Power BI Desktop and click **Refresh**.

Tests: `pytest` and `ruff check .` (tests marked `sql` need the local SQL Server).
